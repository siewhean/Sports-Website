## Proposed compliant architecture (not approved or deployed)

Retain encrypted logical dumps for portability and pre-migration safety. Add a maintained physical-base-backup plus continuous encrypted WAL archive workflow, with bounded archive lag, age-based retention and an independently protected destination region. A logical `pg_dump` cannot be replayed with WAL; physical base backups and an uninterrupted archive chain are required. PostgreSQL can force segment switches with `archive_timeout`, but upload delay also counts toward RPO and missing archive segments break recovery. Archive failures need monitoring because unarchived WAL consumes local disk. See [PostgreSQL 18 continuous archiving](https://www.postgresql.org/docs/18/continuous-archiving.html).

Before selecting a backup tool or changing PostgreSQL settings, the owner must approve a managed multi-AZ host/AZ durability architecture, public-read replica placement/routing, storage regions, data residency, recovery budgets meeting the existing RPO 0/15-minute regional RPO/under-one-hour regional RTO requirements, immutability, restore identity, budget and operator responsibility. Managed multi-AZ and replica hosting add provider costs and failover/routing complexity beyond archive storage; no cost quotation is inferred from the present VM. A candidate tool must support PostgreSQL 18 and OCI's storage interface, verify remote durability, prevent overwriting conflicting WAL segments and preserve its archive chain. Prove this in disposable infrastructure before requesting live authorisation. No new production archiving configuration is activated by this proposal.
